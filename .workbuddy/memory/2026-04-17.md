# 2026-04-17 工作日志

## 修复：模板导入 xlsx 解析失败（Cannot read properties of undefined (reading 'map')）【二次修复】

**根因**：`/import/apply-header` 后端接口用 `Form(...)` 声明参数，但前端发送的是 `Content-Type: application/json` 的 JSON body，导致 FastAPI 无法正确解析，返回错误或空数据；前端拿到 `data.fields` 为 `undefined` 后调用 `.map()` 崩溃。

**修复内容**：
1. `kflower-backend/app/api/v1/endpoints/import_.py`：
   - 新增 `ApplyHeaderRequest` Pydantic 模型（`all_rows: List[List[str]]`, `header_row: int`）
   - 将 `apply_selected_header` 路由参数从 `Form(...)` 改为 `body: ApplyHeaderRequest`
   - 增加对 `all_rows` 元素的字符串强制转换（防止前端传来数字类型导致类型不匹配）

2. `kflower-frontend/src/common/pc/views/Templates.vue`：
   - `applyHeaderRow` 函数中对 `data.fields` 加 `Array.isArray` 判断，防止 undefined 导致 `.map()` 崩溃
   - 所有 `data.*` 字段访问加上默认值（`|| []`、`?? 0`）
   - 字段为空时给出友好提示 `'未能识别到有效字段，请检查表头行是否正确'`

**第二次修复**：实际运行的是 `src/pc/views/Templates.vue`（旧版本），直接在 `/parse` 响应中期望 `fields` 字段（但后端已是两步流程，`/parse` 不返回 `fields`）。
- 重写 `importData` reactive 声明（增加 `potential_headers`、`detected_header_row`、`filename`）
- 重写 `doParseFile`：`/parse` 只存 `all_rows`，再调 `applyHeaderRow` 获取 `fields`

**修复内容**（两个 Templates.vue）：

2. `confirmCreateOrUpdate`：改用 `modules: []`，增加 console.log 和详细错误提示
3. `saveTemplate`：增加 console.log 和详细错误提示
4. `duplicateTemplate`：改用 `modules` 字段
- 新增 `applyHeaderRow` 和 `selectHeaderRow` 函数
- 修正 `reparseWithHeaderRow`：切换表头行只调 `applyHeaderRow`，不重新上传文件

## 修复：模板发布"请输入模板名称"无法跳过（两个 Templates.vue 均有）

**根因**：`publishTemplate` 中 `!tpl.name` 检查没有 `.trim()`，且从 `template` 参数（列表页发布）读取 name 时没有兜底。当 `tpl.name` 为空字符串或纯空格时仍会触发警告。

**修复**：pc 和 common 两个版本的 `publishTemplate` 均改为：
- 列表页发布（有 template 参数）：`template.name || ''`
- 设计器发布（无参数）：直接读 `currentTemplate.name`，末尾 `.trim()` 并取 `.trim()` 结果
- 检查改为 `!nameVal`，提示语改为 `'请在顶部输入模板名称后再发布'`
- **进一步修复**：列表页发布时若模板名称为空（DB 数据问题），自动弹出编辑框让用户补全名称后再继续发布流程（而非直接报错退出）

**修复：编辑模板保存失败（PUT /templates/undefined）**  
`confirmCreateOrUpdate` 中 `editingTemplate.value.id` 为 `undefined` 时直接发请求，导致 422。修复：优先从 `editingTemplate.value.id` 取 ID，兜底用 `currentTemplate.id`，都没有则报错退出。同时完善保存后的列表和设计器状态同步，以及 catch 块错误信息透传。

**修复：列表页发布流程断裂**  
点击列表下拉"发布"→弹出编辑框填名称→保存后弹窗关闭但没有任何后续。根因：`publishTemplate` 中弹出编辑框后直接 `return`，没有继续发布。修复：
1. 新增 `applyTemplateFields()` 从模板对象的 `modules` 提取标准化字段数组（抽自 `openDesigner`）
2. `publishTemplate` 列表页发布时：先将模板数据同步到 `currentTemplate`，再提取 fields，再检查名称
3. 名称为空时给 `editingTemplate.value` 打 `_fromPublish` 标记
4. `confirmCreateOrUpdate` 保存后：若检测到 `_fromPublish`，调用 `continuePublishPreview()` 进入发布预览
5. 新增 `continuePublishPreview()`：同步 currentTemplate → 打开预览弹窗 → 清理 `_fromPublish` 标记

**修复：`confirmCreateOrUpdate` 中 `_fromPublish` 标记被 Vue 响应式代理覆盖**
在 API 调用 **之前** 保存 `fromPublish = !!(editingTemplate.value && (editingTemplate.value as any)._fromPublish)`，之后用保存的变量判断（不再依赖 proxy 上的标记）。错误信息也加上具体 ID 值便于排查。

**新增：卡片状态标签 + 撤回发布**
- 卡片标题旁显示 `el-tag`：已发布→绿色「已发布」，草稿→灰色「草稿」
- 下拉菜单：已发布模板显示「撤回发布」，草稿显示「发布」
- 新增 `unpublishTemplate(t)`：调用 PUT 更新 `is_published: false` → 同步列表 → 同步 currentTemplate
