## Excel 导入功能修复

### 问题描述
用户反馈：在模板设计 → 发布 → 数据管理页面，点击"导入Excel"按钮后，无法上传和导入Excel数据。

### 根本原因
`FormData.vue` 中的导入功能实现有问题：
1. 使用了 `el-upload` 的 `action` 直接上传到后端，但配置错误
2. `handleImportSuccess()` 函数试图在上传成功后解析文件，但上传根本没发生
3. 代码混乱，有未使用的 `uploadUrl` 和 `uploadHeaders` 计算属性

### 修复方案
重构导入流程，改为：
1. **前端解析 Excel**：使用 `xlsx` 库在浏览器端解析文件
2. **三步向导**：
   - 步骤1：上传文件 → 自动解析并预览
   - 步骤2：字段映射 → 将Excel列映射到表单字段
   - 步骤3：确认导入 → 调用后端API导入数据
3. **自动匹配**：根据列名和字段标签自动匹配

### 修改的文件
- `D:\kkflower\kflower-frontend\src\pc\views\FormData.vue`
  - 移除 `el-upload` 的 `action` 和 `on-success` 配置
  - 添加 `:auto-upload="false"` 和 `:on-change="handleFileChange"`
  - 重写 `handleFileChange()` - 验证文件并调用 `parseExcelFile()`
  - 重写 `startMapping()` - 打开字段映射对话框
  - 重写 `confirmImport()` - 调用 `templateAPI.importData()`
  - 删除不再需要的 `uploadUrl` 和 `uploadHeaders` 计算属性
  - 修复 `parseExcelFile()` - 使用 `readAsArrayBuffer`（xlsx库推荐）

## 模板设计导入功能 - 表头行显示限制修复

### 问题描述
用户在模板设计导入 Excel 文件时，发现表头行选择只显示 1-10 行，无法满足复杂表格（多行合并表头）的设计需求。

### 根本原因
多处代码限制了返回和显示的行数：

| 文件 | 位置 | 原限制 | 问题 |
|-----|------|-------|------|
| `import_.py` | 第113行 | `all_rows[:50]` | 返回数据只有50行 |
| `import_.py` | 第94行 | `all_rows[:10]` | 默认候选表头只构建10行 |
| `import_.py` | 第182行 | `rows[:20]` | 预览数据只有20行 |
| `import_service.py` | 第327行 | `min(10, len(all_rows))` | 后端表头检测只检查前10行 |
| `Templates.vue` | 第957行 | `.slice(0, 10)` | 前端多行表头选择只显示10行 |

### 修复方案

#### 后端修复 (`import_.py`)
1. **parse 端点** - 增加返回行数：`all_rows[:50]` → `all_rows[:200]`
2. **默认候选表头构建** - 增加检查范围：`all_rows[:10]` → `all_rows[:50]`
3. **apply-header 端点** - 增加预览行数：`rows[:20]` → `rows[:50]`
4. **字段生成数据行数**：`rows[:50]` → `rows[:100]`

#### 后端修复 (`import_service.py`)
- 表头检测范围：`min(10, len(all_rows))` → `min(30, len(all_rows) // 2 + 1)`

#### 前端修复 (`Templates.vue`)
1. 移除多行表头选择的行数限制：`.slice(0, 10)` → 显示全部行
2. 增加显示行数预览：从 `slice(0, 5)` → `slice(0, 8)`
3. 增加容器高度：`max-height: 300px` → `max-height: 400px`
4. 添加总行数提示：`共 {{ total }} 行`

- `kflower-backend/app/api/v1/endpoints/import_.py`
