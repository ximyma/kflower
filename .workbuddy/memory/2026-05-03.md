## Excel 导入功能修复

### 问题描述
用户反馈：在模板设计 → 发布 → 数据管理页面，点击"导入Excel"按钮后，无法上传和导入Excel数据。

### 根本原因
`FormData.vue` 中的导入功能实现有问题：
1. 使用了 `el-upload` 的 `action` 直接上传到后端，但配置错误
2. `handleImportSuccess()` 函数试图在上传成功后解析文件，但上传根本没发生
3. 代码混乱，有未使用的 `uploadUrl` 和 `uploadHeaders` 计算属性

### 修复方案
重构导入流程，改为：
1. **前端解析 Excel**：使用 `xlsx` 库在浏览器端解析文件
2. **三步向导**：
   - 步骤1：上传文件 → 自动解析并预览
   - 步骤2：字段映射 → 将Excel列映射到表单字段
   - 步骤3：确认导入 → 调用后端API导入数据
3. **自动匹配**：根据列名和字段标签自动匹配

### 修改的文件
- `D:\kkflower\kflower-frontend\src\pc\views\FormData.vue`
  - 移除 `el-upload` 的 `action` 和 `on-success` 配置
  - 添加 `:auto-upload="false"` 和 `:on-change="handleFileChange"`
  - 重写 `handleFileChange()` - 验证文件并调用 `parseExcelFile()`
  - 重写 `startMapping()` - 打开字段映射对话框
  - 重写 `confirmImport()` - 调用 `templateAPI.importData()`
  - 删除不再需要的 `uploadUrl` 和 `uploadHeaders` 计算属性
  - 修复 `parseExcelFile()` - 使用 `readAsArrayBuffer`（xlsx库推荐）

### 数据库变更
❌ 无 - 本次修改不涉及数据库结构变更

## OCR 配置保存失败修复

### 问题描述
用户报告在系统配置的AI配置页面，OCR配置保存失败，提示 "Not authenticated"

### 根本原因
`Settings.vue` 中的 OCR 相关函数（`saveOcrConfig`、`testOcr`、`autoDetectTesseract`）使用了原生 `fetch` 而不是封装的 `axios` 实例，导致请求没有携带认证 token

### 修复方案
1. `saveOcrConfig` - 改用 `localAIAPI.ocrConfigure()` 发送请求
2. `testOcr` - 改用 `localAIAPI.ocrText()` 发送请求，并正确创建 File 对象
3. `autoDetectTesseract` - 改用 `localAIAPI.ocrStatus()` 发送请求

## Embedding 配置页面优化

### 问题描述
1. 保存 embedding 模型配置时报 422 错误
2. 模型 ID 只能用下拉选择，不允许自定义
3. 没有测试模型可用性的功能

### 根本原因
1. **422 错误**：后端 `local_ai.py` 中 `model_config: dict` 缺少 `Body(...)`，FastAPI 把它当成 query 参数
2. **模型 ID 限制**：`el-select` 下拉框体验差，用户无法自由输入
3. **无测试功能**：后端有 `testEmbedModel` 端点但前端未接入

### 修复方案

#### 后端修复（`local_ai.py`）
- 导入 `Body` from fastapi
- `embed_add_model` 参数改为 `model_config: dict = Body(...)`
- `embed_update_model` 参数改为 `model_config: dict = Body(...)`

#### 前端修复（`Settings.vue`）
1. 模型 ID 输入框：下拉选择 → 自由文本输入（`el-input`）
2. 模型名称：必填 → 可选（空时自动用模型 ID）
3. 添加「测试模型」按钮（先保存再调用测试 API）
4. 切换 provider 时不清空模型 ID

## AI 服务健康检查系统

### 问题描述
1. 用户配置了 OCR 和 Embedding 本地模型，但系统仍显示 "Embedding API未配置"
2. OCR 配置后仍显示"无法使用"
3. 没有系统启动时的健康检查，用户无法直观了解哪些 AI 服务可用

### 根本原因
1. **OCR 检查**：后端 `ai-config-status` 只调用 `pytesseract.get_tesseract_version()`，没有使用 `ocr_service.tesseract_path` 配置
2. **Embedding 检查**：用户添加本地模型后，`embedding_provider` 没有自动切换，导致判断逻辑错误
3. **无启动检查**：`main.py` lifespan 中没有任何 AI 服务健康检查

### 修复方案

#### 后端修复（`system.py`）
1. OCR 可用性检查：改用 `ocr_service.is_configured()` 方法
2. Embedding 可用性检查：改进判断逻辑，如果有本地模型就返回 `available=true`
3. 返回数据新增 `local_models` 字段，包含本地模型列表
4. warnings 中添加 OCR 警告

#### 后端修复（`main.py`）
添加 `_check_ai_services()` 函数，在启动时检查：
- OCR（Tesseract 路径是否配置且可用）
- Embedding（sentence-transformers 是否安装，是否配置了模型）
- Jieba（是否安装）
- Reranker（是否配置了可用模型）

#### 前端修复（`Settings.vue`）
1. 改进 Embedding 状态显示：显示本地模型数量
2. 改进 OCR 状态显示："已就绪" / "未配置"
3. 添加"一键检测"按钮：测试所有 AI 服务是否真正可用
4. 添加 `testAllAIServices()` 函数
