# 2026-05-02 工作日志

## 修复仪表盘保存失败问题 (07:37-08:00)

### 问题描述
用户报告"我的应用 设计 仪表盘 无法保存，刷新后数据丢失"，错误信息：
```
fastapi.exceptions.ResponseValidationError: 1 validation errors:
  {'type': 'list_type', 'loc': ('response', 'workflow_node_mapping'),
   'msg': 'Input should be a valid list', 'input': {}}
```

### 根本原因
`workflow_node_mapping` 字段在 Pydantic schema 中定义为 `Optional[List[Dict]] = []`（列表类型），
但数据库中存储的是 `{}`（空字典），导致 FastAPI 响应验证失败。

### 修复内容

#### 1. 代码修复 (service.py)
- `add_menu` 方法：添加 `workflow_node_mapping=[]` 初始化
- `update_menu` 方法：返回时验证类型 `isinstance(menu.workflow_node_mapping, list) else []`
- `get_app` 方法：返回菜单数据时包含 `workflow_node_mapping` 字段，并验证类型
- `get_menu_tree` 方法：验证 `workflow_node_mapping` 类型

#### 2. 数据修复
创建并运行迁移脚本，修复数据库中现有 8 条记录的 `workflow_node_mapping` 字段类型：
- Menu 1-8: `{}` (dict) → `[]` (list)

#### 3. 模型默认值修复 (models.py)
- 第73行: `workflow_node_mapping = Column(JSON, default=dict, ...)`
  改为: `workflow_node_mapping = Column(JSON, default=list, ...)`
- 这样下次数据库重新初始化时，新记录的默认值就是空列表 `[]` 而不是空字典 `{}`

### 修改文件
- `D:\kkflower\kflower-backend\app\modules\my_apps\service.py`
- `D:\kkflower\kflower-backend\app\modules\my_apps\models.py`

### 验证结果
所有菜单记录的 `workflow_node_mapping` 字段类型已正确转换为 list。
