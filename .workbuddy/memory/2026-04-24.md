### 发现的问题和修复

#### 1. 公式引擎中文字段名冲突（严重）
**问题描述：**
- `{单价} * {数量}` 计算结果是 10000 而不是 500
- 调试发现：`单价` 和 `数量` 都被转换成了相同的安全变量名 `_f___`
- 导致后一个值覆盖了前一个值，实际计算是 `100 * 100 = 10000`

**根本原因：**
`formula_engine.py` 第 423 行的正则表达式：
```python
safe_name = '_f_' + re.sub(r'[^a-zA-Z0-9]', '_', field_ref)
```
把所有非字母数字字符（包括中文）都替换成下划线，导致：
- `单价` → `___` (3 个下划线)
- `数量` → `___` (3 个下划线)

**修复方案：**
改用 Unicode 编码确保唯一性：
```python
unicode_parts = [hex(ord(c))[2:] for c in field_ref.replace('.', '__')]
safe_name = '_f_' + field_ref.replace('.', '__') + '_' + '_'.join(unicode_parts)
```
结果：
- `单价` → `_f_ 单价_5355_4ef7`
- `数量` → `_f_ 数量_6570_91cf`

**测试验证：**
```python
formula_engine.evaluate('{单价} * {数量}', {'单价': 100, '数量': 5})
# 返回：500 ✓
```

#### 2. 子表字段引用 AST 安全检查失败
**问题描述：**
- `SUM({items.amt})` 被判定为不安全 AST 节点，返回 None
- 原因：`.` 被解析为 `ast.Attribute`，不在白名单中

**修复方案：**
在 `ALLOWED_NODE_TYPES` 中添加 `ast.Attribute`：
```python
ALLOWED_NODE_TYPES = {
    # ... 原有类型 ...
    ast.Attribute,  # 支持子表字段引用
}
```

**测试验证：**
```python
formula_engine.evaluate('SUM({items.amt})', {'items': [{'amt': 10}, {'amt': 20}, {'amt': 30}]})
# 返回：60.0 ✓
```

## 修复前端 Vite 构建错误（模板设计/我的应用打不开）

**问题：** `AIAppGeneratorDialog.vue` 和 `KnowledgeSearch.vue` 使用了错误的相对路径导入
- 文件位于 `src/pc/views/my-apps/components/`
- 错误路径：`../../common/api/...` → 解析为 `src/pc/views/my-apps/common/api/...`（路径不存在）
- 正确路径应为 `@/common/api/...`（`@` = `src/`）

**修复：**
- `AIAppGeneratorDialog.vue`：`../../common/api/myApps` → `@/common/api/myApps`
- `KnowledgeSearch.vue`：`../../common/api` → `@/common/api`

**影响范围：** Vite import-analysis 构建失败，导致整个前端模块树无法加载（模板设计、我的应用全部打不开）
