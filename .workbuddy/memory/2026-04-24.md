## 智能表单提交500错误修复

### 问题现象
用户在模板设计创建"货物采购单"，保存并发布后提交数据报500错误。

### 问题根因
`templates.py` 的 `submit_template_data` 函数中使用了 `template.fields`，但 Template 模型没有 `fields` 列，字段存储在 `modules` JSON 中。导致 AttributeError 从而返回 500 错误。

### 修复内容
**文件**: `kflower-backend/app/api/v1/endpoints/templates.py`

将：
```python
field_labels = {f.get("name", ""): f.get("label", f.get("name", "")) for f in template.fields}
for field in template.fields:
```

改为：
```python
# 从 modules 中提取所有字段（兼容新旧格式）
all_template_fields = []
modules_list = template.modules or []
if isinstance(modules_list, str):
    import json as _json
    modules_list = _json.loads(modules_list) if modules_list else []

for mod in modules_list:
    if isinstance(mod, dict) and 'fields' in mod:
        all_template_fields.extend(mod['fields'] or [])

field_labels = {f.get("name", ""): f.get("label", f.get("name", "")) for f in all_template_fields}
for field in all_template_fields:
```

- 后端模块导入：OK
- 数据库状态：货物采购单(ID=14)已发布，form_data_14表存在

## 智能表单系统全面测试

### 测试范围
对智能表单系统升级后的代码进行全面测试，查找并修复错误。

### 发现的问题和修复

#### 1. 公式引擎中文字段名冲突（严重）
**问题描述：**
- `{单价} * {数量}` 计算结果是 10000 而不是 500
- 调试发现：`单价` 和 `数量` 都被转换成了相同的安全变量名 `_f___`
- 导致后一个值覆盖了前一个值，实际计算是 `100 * 100 = 10000`

**根本原因：**
`formula_engine.py` 第 423 行的正则表达式：
```python
safe_name = '_f_' + re.sub(r'[^a-zA-Z0-9]', '_', field_ref)
```
把所有非字母数字字符（包括中文）都替换成下划线，导致：
- `单价` → `___` (3 个下划线)
- `数量` → `___` (3 个下划线)

**修复方案：**
改用 Unicode 编码确保唯一性：
```python
unicode_parts = [hex(ord(c))[2:] for c in field_ref.replace('.', '__')]
safe_name = '_f_' + field_ref.replace('.', '__') + '_' + '_'.join(unicode_parts)
```
结果：
- `单价` → `_f_ 单价_5355_4ef7`
- `数量` → `_f_ 数量_6570_91cf`

**测试验证：**
```python
formula_engine.evaluate('{单价} * {数量}', {'单价': 100, '数量': 5})
# 返回：500 ✓
```

#### 2. 子表字段引用 AST 安全检查失败
**问题描述：**
- `SUM({items.amt})` 被判定为不安全 AST 节点，返回 None
- 原因：`.` 被解析为 `ast.Attribute`，不在白名单中

**修复方案：**
在 `ALLOWED_NODE_TYPES` 中添加 `ast.Attribute`：
```python
ALLOWED_NODE_TYPES = {
    # ... 原有类型 ...
    ast.Attribute,  # 支持子表字段引用
}
```

**测试验证：**
```python
formula_engine.evaluate('SUM({items.amt})', {'items': [{'amt': 10}, {'amt': 20}, {'amt': 30}]})
# 返回：60.0 ✓
```

## 修复前端 Vite 构建错误（模板设计/我的应用打不开）

- 错误路径：`../../common/api/...` → 解析为 `src/pc/views/my-apps/common/api/...`（路径不存在）

**修复：**
- `AIAppGeneratorDialog.vue`：`../../common/api/myApps` → `@/common/api/myApps`

## 修复 AI 设计助手（AI Design）功能

### 问题描述
1. 点击"AI设计"后，输入提示词，立即显示"应用已生成"，1秒都不到
2. 原因是后端没有实现 `/api/v1/ai-design/generate` 接口

### 根本原因
`AIDesigner.vue` catch 块中有 `generateMockDesign()` 自动调用，导致请求失败时仍显示模拟数据：
```javascript
} catch (e: any) {
  ElMessage.error('生成失败：' + ...)
  // 演示模式：生成模拟数据
  generateMockDesign()  // <-- 问题在这里
}
```

### 修复内容
1. **后端新增接口**：`app/modules/my_apps/endpoints_ai_design.py`
   - `POST /ai-design/generate` - 调用 AI agent 生成设计方案
   - `POST /ai-design/apply/{app_id}` - 应用设计方案到指定应用

2. **API 路由注册**：在 `api.py` 中注册 `endpoints_ai_design.router`

3. **前端修改**：`AIDesigner.vue`
   - 移除 catch 块中的 `generateMockDesign()` 自动调用
   - 改进错误提示，区分超时、配置错误等
   - 不再自动使用演示模式，让用户看到真实错误
