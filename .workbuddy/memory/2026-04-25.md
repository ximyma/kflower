## 修复仪表盘保存后数据丢失问题

### 问题
用户在"货物采购"应用中添加仪表盘组件、保存、发布后，进入应用首页仪表盘空白，再进入设计界面查看，原来保存的组件也不见了。

### 根因分析

**问题1：后端 aiosqlite JSON 字符串未解析（核心原因）**
`endpoints_dashboard.py` 的 GET 和 PUT 端点直接使用 `app.config`，但 aiosqlite 下 SQLAlchemy 的 JSON 类型字段返回的是**原始 JSON 字符串**而非 Python dict。`app.config.get("dashboard")` 在字符串上调用会抛出异常或返回错误结果，导致保存时数据未正确写入，加载时也读不到。

之前 `templates.py` 中所有端点都已修复此问题（`isinstance(config_raw, str)` → `json.loads()`），但 `endpoints_dashboard.py` 遗漏了。

**问题2：前端 appId 缺乏 fallback 机制（次要）**
`AppDashboard.vue` 和 `DashboardDesigner.vue` 都依赖 `props.appId`，但路由传递可能失败（`<router-view>` 上的 attributes 不一定会传递给子组件），导致 `appId` 为 `undefined`。

### 修复

1. **`endpoints_dashboard.py`**：
   - 添加 `_parse_config()` 辅助函数，兼容 aiosqlite JSON 字符串
   - GET 和 PUT 端点都使用 `_parse_config(app.config)` 解析配置
   - 添加 `import json`

2. **`AppDashboard.vue`**：
   - 添加 `resolvedAppId` computed，优先使用 `props.appId`，fallback 到 `route.params.appId`
   - 所有 API 调用改为使用 `resolvedAppId.value`

3. **`DashboardDesigner.vue`**：
   - 添加 `useRoute` 导入和 `resolvedAppId` computed
   - 所有 API 调用改为使用 `resolvedAppId.value`

### 验证
- `_parse_config` 在 dict、字符串、空 dict、None 四种场景下均能正确处理
- 后端使用 `--reload` 模式运行，修改自动生效
- 所有文件 lint 通过
